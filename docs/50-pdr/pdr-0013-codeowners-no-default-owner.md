# CODEOWNERSの雛形には、既定の持ち主を置かない

- 日付: 2026-10-23
- 状態: stable

## 背景

`.github/CODEOWNERS.example`（[PDR-0009](./pdr-0009-codeowners-example.md)）は、挙げたパスにだけ持ち主を書いている。`tests/`、`production/`、`src/`のうち`core/`と`networking/`の外のように、どの行にも当たらないパスがある。そのパスを変えるPRには、レビュアーが自動では付かない（setopic/game-template#39）。

GitHubの`CODEOWNERS`では、先頭に`*`の行を置くと、ほかの行に当たらないパスの持ち主になる。[PDR-0012](./pdr-0012-codeowners-review-required.md)で、複数人で開発するときは持ち主の承認を必須にした。そのうえで`*`の行を置くと、すべてのPRに持ち主の承認が要る。

## 決定

`CODEOWNERS.example`に、`*`の行を置かない。どの行にも当たらないパスを変えるPRは、mainの保護の「承認1人以上」により、誰か1人が承認すればマージできる。このことを、`CODEOWNERS.example`の冒頭の注記に書く。

## 理由

どの行にも当たらないパスは、ゲームプレイのコード、テスト、ストーリーやスプリントの記録のように、ストーリーごとに担当が変わるものである。決める人がパスで決まらないので、持ち主を固定しても、その人がほかの人の作業を承認するだけになる。

持ち主の承認を必須にしたので、`*`の行を置くと、すべてのPRがその持ち主1人の承認を待つ。`*`の行を置かなくても、「承認1人以上」でPRは誰か1人が見る。

## 却下した案

| 案 | 却下理由 |
| --- | --- |
| `*`の行を置き、テンプレートの管理者を既定の持ち主にする | すべてのPRが管理者1人の承認を待ち、そこで止まる |
| `*`の行を置き、作品が既定の持ち主を選ぶ | どの役割を選んでも、すべてのPRがその持ち主の承認を待つ。担当がストーリーごとに変わるパスに、固定の持ち主を置くことになる |

## 影響

`CODEOWNERS.example`の行は変わらない。冒頭の注記が増える。どの行にも当たらないパスを変えるPRには、レビュアーが自動では付かないので、PRを出す人がレビュアーを選ぶ。

## 見直しの条件

どの行にも当たらないパスのPRで、レビュアーが付かないまま止まることが多いとき。持ち主の承認を必須にする決定（PDR-0012）を見直したとき。
