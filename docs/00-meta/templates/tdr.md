<!--
TDRとADRの雛形である（PDR-0006）。節は、CCGSのADRの雛形の節を1対1で日本語にしたものである。
tdr.mdとadr.mdは、フロントマターのtype（newが--typeで上書きする）のほかは同じ中身にする。
CCGSのスクリプト（adr-status.sh）は、この雛形の`##`の節と、[角かっこ]の行を読む。
[角かっこ]の行が埋まっていないと、まだ書いていないものとして数える。書くことの無い節は「なし」と書く。

状態は本文に書かず、フロントマターの`status`だけに持つ。CCGSの状態との対応は次のとおりである。

    Proposed    draftかreview
    Accepted    stable
    Deprecated  deprecated
    Superseded  deprecated。後継の記録が、フロントマターのsupersedesでこの記録を指す

`stable`にしてよいのは、利用者か、利用者がはっきり認めたうえでの`technical-director`だけである。
ほかのエージェントやスキルは、自分の判断で`stable`にしない。
`draft`か`review`の記録を指すストーリーは止まり、エピックは`stable`の記録を求めるので、決める人を名指しにしている。

置き換えるときは、新しい記録の`supersedes`に古い記録のidを書き、古い記録の`status`を`deprecated`にする。
前提にするTDRとADRは、「前提のADR」の節の「前提」の行に加えて、フロントマターの`depends_on`にも書く。
graphの`check`が、`depends_on`の循環と向きを確かめる。
-->

知識のリスクがMEDIUMかHIGHなら、エンジンの版を上げたときに確かめ直す。

「層」は、この記録自身の層であり、この記録を指すエピックの層ではない。「分野」とも別の分け方である。
いくつかのスキル（/create-stories、/create-epics、/architecture-decision、/story-readiness、
/propagate-design-change）とgate-pre-production.mdが、Foundationの層の記録を重要なものとして扱う。
この行が無い記録も、重要なものとして数える。/create-storiesはstandardのとき、重要な記録が無ければ止まり、

Foundationの層の記録をCoreの層のエピックが指すことはよくあるので、指すエピックから層を推し量らない。

値は、エピックとストーリーが使っているFoundation / Core / Feature / Presentationの4つである。
5つめの値を作らず、「分野」の値も使わない。「分野」はエンジンのどの部分に関わるか、
